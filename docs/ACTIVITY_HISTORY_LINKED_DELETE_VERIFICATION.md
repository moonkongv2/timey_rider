# 활동 기록 선택적 연동 삭제 구현·검증

## 구현 결과

- 기본값은 기록만 삭제. 매번 해제된 체크박스로 시작하며, 실제 지급 스티커나 미사용 보상판 연결 칸이 있을 때만 연동 삭제 옵션을 표시한다.
- 실제 기록의 rewardIds 빈도로 보관함을 차감하고 미사용 보상판의 해당 세션 칸만 제거한다. 목표 미달 달성 보상은 진행 중으로 복귀하고 달성 날짜를 비운다. 사용한 보상 목록과 원시 저장값은 삭제 경로에서 변경하지 않는다.
- 두 삭제 방식 모두 로컬 삭제 ID를 남겨 늦은 완료 저장·pending 재개가 재지급하지 못하도록 한다. null sessionId 직접 결과는 endedAt 기반 ID를 사용하며 다른 pending 정리에는 사용하지 않는다.
- 진행 데이터 읽기·복구·완료·삭제·보상 변경은 여러 서비스 인스턴스가 공유하는 큐를 사용한다. 부분 스냅샷 저널은 전체 구조 검증 후 삭제 ID를 먼저 적용하고, 해당 데이터 키의 레거시 원본만 정리한다.
- 보상 변경은 서비스 내부의 엄격한 무손실 디코더로 전체 슬롯과 확장 필드를 보존한다. 화면용 공용 모델 파서는 변경하지 않았다. 진행 중 보상판 조회의 2개 제한을 제거하고 생성 제한만 유지한다. 홈에는 2개 요약과 나머지 개수를 표시한다.
- 결과 화면은 사전 확인 후 선택/저장을 진행한다. 기록 성공과 pending 정리 성공 후에만 미디어를 시작한다. 정리 실패 재시도는 기록 성공 결과를 재사용하고 삭제 상태를 다시 확인한다.
- pending 선택 갱신은 저장소 큐 안에서 동일 ID일 때만 수행한다. 정리는 동일 ID의 잔여 active/legacy active와 pending만 제거한다. 완료 handoff 중 active 제거 실패도 보고하고 재시도할 수 있다.
- Home/ActivityHistory/RewardGoal/StickerCollection의 진행 조회 오류에 재조회 UI를 제공한다. 변경 실패는 데이터 오류와 저장 결과 미확정을 구분하고 입력 상태를 유지한다.
- 5개 언어 삭제 정책, 보상판 채움 조건, 생성 제한, 사용 안내와 심사 절차를 갱신했다. 큰 글씨에서 발견한 활동 카드의 제목/상태/스티커 글자 넘침을 수정했다.

## 계획의 구현 세부 보완

1. 기존 `activityRecordTransaction`의 키→StringList 형태를 유지하되, **보상 사용 작업에만** 선택적 `legacyUsedSourceToRemove` 메타데이터를 추가했다. 실제 저장 데이터 키가 아니며 값은 `usedRewardGoals` 또는 `redeemedRewardGoals` 하나로 제한한다. 메타데이터가 있으면 used 스냅샷도 필수다. 재시작 복구가 이미 기록된 신규 used 키만 보고 이관 원본을 추정하면 가려진 하위 우선순위 키를 지울 수 있으므로, 선택한 원본을 명시적으로 보존한다. 구형 저널은 이 필드 없이 그대로 복구한다. 삭제 트랜잭션에는 used 스냅샷이나 이 메타데이터가 없다.
2. SharedPreferences는 디스크 쓰기 실패를 보고하기 전에 캐시를 변경한다. false/예외가 발생하면 캐시를 다시 읽어, 미기록 저널을 성공한 것처럼 복구하거나 삭제되지 않은 잔여 타이머를 숨기지 않도록 했다. 쓰기 후 예외도 별도로 검증한다.
3. 후속 완료 저장도 손상/중복 재고를 건너뛰어 덮어쓰지 않고 중단한다. 조회에서 손상된 개별 항목을 건너뛰는 기존 동작은 유지한다.
